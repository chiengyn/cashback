# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

HoànTiền: a cashback app for Vietnamese shoppers. A user pastes or shares a Shopee / Lazada / TikTok Shop product link, the backend converts it to an affiliate link carrying a per-click `sub_id`, the user buys on the marketplace app, and a share of the commission (default 70%) lands in their in-app wallet once the marketplace approves the order.

- `docs/design.html` — the high-level design (system design, UI/UX, mobile, deployment, roadmap). It is published as a claude.ai artifact (https://claude.ai/artifact/9PVERQExzFgboCwdmwLw2Q); republish the same file path after editing so the link stays the same. Written in Vietnamese.
- `mobile/` — the React Native app (Expo SDK 57, Expo Router, TypeScript).
- `backend/` — Next.js 16 API + admin pages + Vercel Cron, Postgres via Drizzle ORM. See `backend/README.md`.

User-facing copy in the app and docs is Vietnamese.

## Mobile commands

Run from `mobile/`:

```bash
npm install
npx expo run:android            # dev build; Expo Go does NOT work (expo-share-intent needs native code)
npx expo run:ios                # macOS only; otherwise: npx eas-cli@latest build --profile development --platform ios
npx tsc --noEmit                # typecheck
npx expo lint                   # ESLint (eslint-config-expo, includes React Compiler rules)
npx expo-doctor                 # dependency/config check
npx expo export --platform android   # quick check that the bundle builds
npx expo install <pkg>          # always use this instead of npm install to get SDK-compatible versions
```

There is no test runner set up yet. Run typecheck and lint before calling a change done.

`mobile/AGENTS.md` (from the Expo template) applies: Expo APIs change every SDK, so check the versioned docs at `https://docs.expo.dev/versions/v57.0.0/` before using an Expo/RN API instead of relying on memory; never hand-edit `ios/`/`android/` (generated by prebuild, gitignored) — configure native behaviour through `app.json` plugins.

## Mobile architecture

- **Routing** (`src/app/`, Expo Router): root `_layout.tsx` nests `ShareIntentProvider` (must be outermost) → `SessionProvider` → `ThemeProvider` → `Stack`. `(tabs)/_layout.tsx` uses `NativeTabs` from `expo-router/unstable-native-tabs` (the SDK 55–57 import path; SDK 58+ moves it to `expo-router/native-tabs`).
- **Share flow:** the marketplace app's Share sheet opens our app. On iOS the share extension deep-links `hoantien://dataUrl=…`, which `src/app/+native-intent.ts` redirects to `/`. The home tab reads `useShareIntentContext()` and pushes `/preview?url=<raw shared text>`. `preview.tsx` extracts the product URL with `extractProductLink` (`src/lib/links.ts`) because shared text includes product title and price around the URL.
- **"Mua ngay" (buy) flow:** `preview.tsx` requires a session, calls `POST /api/clicks/{id}/open` to get the affiliate URL, then `Linking.openURL(affiliateUrl)` directly. Do not route the app through the web `/r/{click_id}` 302 page: iOS often won't open the marketplace app from a universal link behind a redirect, which loses attribution.
- **API layer** (`src/lib/api.ts`): the endpoint contract the future backend must implement is documented at the top of the file. If `EXPO_PUBLIC_API_URL` is unset, `api` is swapped for `mockApi` (`src/lib/mock.ts`) with the same signatures — keep the two in sync when adding endpoints. Mock login accepts any phone and any 6-digit OTP.
- **Auth:** `src/lib/session.tsx` stores `{ token, phone }` in `expo-secure-store` and pushes the token into `api.ts` via `setAuthToken`. Screens that need login wrap content in `RequireLogin` (`src/components/require-login.tsx`).
- **Data loading:** `useAsync(fn, { refetchOnFocus })` in `src/lib/use-async.ts` instead of a query library. `fn` must be a stable reference (`api.orders`, or `useCallback`). State updates happen inside promise callbacks on purpose: the `react-hooks/set-state-in-effect` lint rule rejects synchronous `setState` in effects. Don't use `refetchOnFocus` on `preview.tsx`, since each fetch creates a new click.
- **Styling:** plain `StyleSheet`, tokens in `src/constants/theme.ts`. The app is light-only (`userInterfaceStyle: "light"`) with a bright orange-pink palette; the primary colour is deliberately not any marketplace's exact brand colour.

## Backend architecture

- **Layers:** `src/app/**/route.ts` handlers are thin — wrapped in `route()` from `src/lib/http.ts`, which turns `HttpError` / zod errors into `{ message }` JSON (Vietnamese, shown verbatim by the app). Logic lives in `src/services/`; pure rules in `src/lib/` (unit-tested without a DB).
- **Response shapes must match `mobile/src/lib/types.ts`** — that file is the API contract.
- **Platforms:** `src/platforms/index.ts#getAdapter` picks `MockAdapter` when `AFFILIATE_MODE=mock` (default outside production), `ShopeeAdapter` when Shopee credentials are set, else a not-configured adapter (Lazada/TikTok have no real integration yet). Shopee field names, signing and status values come from third-party docs and are flagged as needing verification.
- **Link creation** (`services/links.ts`): extract URL from shared text → `resolveProductLink` follows short-link redirects **only within marketplace domains** (SSRF guard) → `products` row doubles as the 6-hour product cache → click reused if the same user pasted the same product within 24 h → new 10-char base62 click id sent to the platform as `sub_id`. Rate limits count recent rows in `clicks` / `otp_codes` (no Redis).
- **Money:** VND integers. Wallet balance is never stored; it is `SUM(pending_delta)` / `SUM(available_delta)` over append-only `ledger_entries`. `planLedger` in `src/lib/cashback.ts` is the single source of truth for which entries a status change writes; `conversions.credited_pending/credited_available` remember what each order put in each bucket. Partial unique indexes on `(conversion_id, type)` / `(withdrawal_id, type)` stop duplicate entries. Withdrawals lock the user row (`FOR UPDATE`) before checking balance.
- **Order sync:** three Vercel Cron routes `/api/cron/sync-orders/{purchase|complete|reconcile}` (schedules in `vercel.json`), each looping over platforms with a per-job row lock in `cron_jobs` (`services/cron-lock.ts`: `INSERT … ON CONFLICT DO UPDATE … WHERE locked_until < now() RETURNING`, TTL 10 min > `maxDuration` 300 s). The cursor advances only when every page was fetched. Orders become `approved` once the platform reports completion and `APPROVAL_HOLD_DAYS` have passed (`promoteMatured` runs after each sync).
- **Raw SQL gotcha:** in raw `sql` template literals pass dates as ISO strings — postgres.js with `prepare: false` rejects `Date` params (the query builder converts them, raw SQL does not).
- **Auth:** phone + OTP (codes HMAC'd with `AUTH_SECRET`; SMS provider is console-only for now) or Sign in with Apple (`services/apple.ts`: identity token verified against Apple JWKS, `aud` = `APPLE_BUNDLE_ID`) → opaque session token, stored as sha256 in `sessions`. Apple accounts start with `users.phone = null` and must link a phone via OTP (`/api/auth/verify` with the Apple session's token) before withdrawing — this keeps "one phone, one paid account". Account deletion nulls phone/apple_sub, deletes sessions and calls Apple `/auth/revoke` (App Store requirement); orders and ledger are kept. Admin pages use Basic Auth in `src/proxy.ts`, re-checked in pages/actions via `requireAdmin()`.
